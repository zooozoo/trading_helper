# 실거래 기록 대조와 전략 수정 원칙

상태: 2026-10-04 작성. 모의투자와 실거래 모두에 적용합니다. 둘은 `data_kind`로 구분해 섞지 않습니다.

## 목적 두 가지를 분리한다

1. **실행 대조**: 백테스트가 가정한 체결 방식대로 실제로 했는가. 매주 수행합니다.
   여기서 고치는 것은 비용표, 슬리피지 가정, 운영 절차입니다.
2. **전략 평가**: 전략이 유효한가. 실거래 손익은 이 질문의 **출처**이지 **근거**가 아닙니다.
   답은 과거 데이터 전체의 백테스트로 냅니다.

## 입력: `data/templates/trades.csv`

`trade_id,signal_id,symbol,side,trade_date,fill_time,fill_price,quantity,fee,tax,order_type,order_reason,broker_ref,note,recorded_at`

- 체결 단위로 한 행. 부분 체결은 체결마다 한 행, 같은 `signal_id`.
- `signal_id`: 일요일 산출물의 신호 ID(공시 접수번호 기반). 신호 없는 임의 매매는 `MANUAL-...`로 적고
  전략 성과에서 제외합니다.
- `side`: `buy` / `sell`. `trade_date`: 체결일 ISO. `fill_time`: 체결 시각(HH:MM, 모르면 비움).
- `fill_price`, `quantity`: 증권사 체결 내역 그대로. `fee`, `tax`: 원 단위 실제 금액. 추정치 금지.
- `order_type`: `limit_open`(개장 동시호가 지정가), `market_open`(개장 동시호가 시장가), `other`.
  v1 절차대로면 매수는 `limit_open`, 매도는 `market_open`만 나와야 합니다.
- `order_reason`: `entry`, `stop`, `target`, `time_exit`, `halt`, `manual`.
- `recorded_at`: 기록 시각. 체결일보다 빠를 수 없습니다.
- 검증: `python -m trading_helper validate --trades <csv>`.

## 대조 항목 (매주, 코드가 계산)

| 항목 | 계획(일요일 산출물) | 실제(trades.csv) | 어긋나면 |
|---|---|---|---|
| 진입 체결 | M 시가, 상한가 이하일 때만 | `entry` 행의 체결가·수량 | 체결가-시가 차이를 슬리피지 표본으로 기록 |
| 미체결 | M 시가 > 상한가면 거래 없음 | `entry` 행 없음 | 체결됐으면 절차 위반으로 표시 |
| 청산 시점 | 판정 다음 거래일 시가 | `stop`/`target` 행의 날짜 | 하루라도 늦으면 "지연 청산"으로 표시 |
| 기간 종료 | L 시가 | `time_exit` 행 | 없으면 "미청산 포지션" 경고 |
| 수량 | 보고서 수량 | 체결 수량 합 | 차이와 사유 기록 |
| 비용 | 설정 파일 비용표 | fee+tax 합 | 실제 비율이 가정보다 크면 비용표 갱신 후 백테스트 재실행 |
| 주문 방식 | limit_open / market_open | `order_type` | `other`면 절차 위반으로 표시 |

산출: 주별 실행 오차 보고서(계획 대비 체결가 차이 분포, 지연·누락 건수, 실제 비용 비율)와
`data_kind`별 누적 지표(비용 후 수익, 낙폭, 거래 수, 승률). 백테스트 지표와 같은 정의를 쓰되
**같은 표에 합산하지 않습니다.**

## 전략 수정 허용 조건

- 실거래 결과만으로 파라미터를 바꾸지 않습니다. 의문이 생기면 가설을 적고 과거 데이터 백테스트로 검증합니다.
- 수정은 새 전략 버전(v1 → v2)과 실험 번호로 남깁니다. 변경 이유, 시도 횟수, 실패한 시도도 기록합니다.
- 새 버전은 개발/검증 구간을 통과하고, 가능하면 미사용 구간에서도 확인한 뒤에만 실행에 반영합니다.
- 사전 등록 표본 수: 실거래 **30건** 미만에서는 전략 규칙을 바꾸지 않습니다. 숫자는 시작 전에 사용자가 확정합니다.
- 실거래 기간은 가장 깨끗한 미사용 검증 구간입니다. 이 구간에 맞춰 최적화하면 그 가치가 사라집니다.
- 실행 대조에서 발견한 비용·슬리피지 수정은 전략 수정이 아니므로 즉시 반영하되, 백테스트를 그 비용으로 다시 돌려 여전히 통과하는지 확인합니다.

## 중단 조건 (사전 확정, 사용자 입력 필요)

- 누적 낙폭이 사용자가 정한 허용치를 넘으면 신규 진입을 멈추고 원인 분석으로 돌아갑니다.
- 절차 위반(지연 청산, 임의 매매)이 반복되면 전략이 아니라 운영 절차를 먼저 고칩니다.
- 실행 오차가 백테스트 가정과 구조적으로 다르면(예: 시가 체결이 반복적으로 실패) 체결 모델을 수정하고 재검증합니다.
- 허용 낙폭 수치와 중단 후 재개 조건은 모의투자 시작 전에 이 문서에 기록합니다. 아직 미정.
